# Goal Prompt

### Profile and fix the cold-path slowdown in `f`

The first scan of a folder is noticeably slow; subsequent scans are
fast. The user's hypothesis is that expensive calculations (git
status, code metrics, todo scan, languages, ports, docker) are
running on every cold scan without being cached or made lazy.

**Scope:**

1. **Profile the cold path.** Build a small timing harness that
   measures the wall-clock time of a `f <folder>` call on a
   cleared cache, across 3–5 representative targets:
   - small project (this repo)
   - large project (e.g. a node_modules or cargo target dir)
   - a real work folder (e.g. `~/Dev` with mixed projects)
   Record per-feature contribution (git, code metrics, todo scan,
   languages, ports, docker, file metadata, banner assembly).

2. **Identify the bottleneck.** Read the timing output and the
   source. Find the 1–3 features that dominate cold-path time.
   Document findings in `PROFILE_COLD_PATH.md` (created in the
   repo).

3. **Fix the bottleneck(s).** For each top offender, make a
   targeted fix that removes it from the cold path. Plausible
   fixes (to be confirmed by the profile):
   - Defer expensive features to a background task; show banner
     first, fill in features as they become ready.
   - Cache feature results per-folder and invalidate on mtime.
   - Parallelize independent feature computations.
   - Skip features when the target dir is huge (e.g.
     `> 10 000` entries) unless the user opted in.

4. **Re-profile.** Re-run the same harness and confirm the cold
   path is materially faster (target: at least 2× faster on the
   largest test folder, no regression on small folders). Append
   the comparison to `PROFILE_COLD_PATH.md`.

5. **Ship.** Bump version (0.7.7), update `CHANGELOG.md` and
   release notes, publish to crates.io, push tag, create GitHub
   release.

**Success criteria:**

- `PROFILE_COLD_PATH.md` exists with before/after numbers
- Cold-path wall-clock on the largest test folder is at least
  2× faster than before the fix
- All 235 existing tests still pass; new tests cover the
  caching/lazy behaviour
- `f --version` reports 0.7.7 on `~/.local/bin/f`
- crates.io, all 4 git remotes, and GitHub release are in sync

**Boundaries:**

- In scope: cold-path performance, the features above
- Out of scope: hot-path changes (warm scans are already fast,
  per the user), new features, alias/banner logic, doc cleanup

**Constraints:**

- Preserve existing behavior unless explicitly changed
- No TODOs, dead code, or undocumented behaviour changes
- Reuse existing local validation commands; do not invent new CI
- The fix must not regress warm-path performance
- Snake_case function names; no `#[allow(non_snake_case)]`
- Local install path: `~/.local/bin/f`; daemon at `~/.local/bin/fabd`

**If blocked:** stop and ask the user.
