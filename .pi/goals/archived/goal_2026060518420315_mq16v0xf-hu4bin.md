# Goal Prompt

Update `f install` so the reload hint is printed on EVERY run (including re-runs where `~/.zshrc` already has the source line), with a copy-pasteable `source ~/.local/bin/fab-shell.zsh` command — so users who started their terminal before running `f install` immediately see how to activate folder navigation (`f N` → `cd`) without trial-and-error.

## Why
Today, the reload hint only prints on first install (`if installed_any` branch in `src/cmd/install.rs:55`). On re-runs it falls through to "✅ Shell wrappers already installed. No changes needed." with no reminder to reload the current shell. That's exactly the trap you hit: the source line was already in `~/.zshrc`, so re-running `f install` gave no hint, but the running zsh still had the binary-direct `f` cached — so `f 3` printed a path but didn't `cd`, while `f <file>` "worked" because the binary handles files directly without needing the shell function.

## Success criteria
1. `f install` prints, on every run, a clearly-formatted block containing:
   - The exact `source ~/.local/bin/fab-shell.zsh` command (copy-pasteable)
   - The equivalent for bash if `~/.bashrc` exists
   - A short explanation that the source line in the rc file affects NEW shells only, not the current one
2. The "Shell wrappers already installed. No changes needed." message is replaced/augmented so it never appears WITHOUT the reload hint.
3. After the fix, the user can run `f install` and immediately know what to paste into their current terminal — no need to re-read docs.
4. `f N` for a folder N in a freshly-loaded shell cds into the folder (verifiable by running `cd /tmp && source ~/.local/bin/fab-shell.zsh && f 5 && pwd`).
5. Build clean, `cargo test --lib` passes, binary reinstalled to `~/.local/bin/f`, change committed and pushed to `main`.

## Boundaries
**In scope:** Editing `src/cmd/install.rs` output formatting, possibly extracting a small `print_reload_hint()` helper, updating the bash/zsh hint text. Touching `fab-shell.zsh` / `fab-shell.bash` only if the change requires it (it shouldn't).

**Out of scope:** Changing the source-line write logic, adding `.zshenv` support, auto-detecting whether the function is loaded (that's a separate smart-detection feature), changing the `f` binary's arg routing, fixing any unrelated bugs.

## Constraints
- Must not change behavior for first-time installs (still writes the source line and prints "Added source line to ~/.zshrc").
- Must not break the existing "already has source line" idempotency check.
- Should not print the bash hint if `~/.bashrc` doesn't exist (preserve current behavior).
- Output must be plain terminal text, no ANSI colors that would interfere with copy-paste.

## Verification contract
- `cargo build` succeeds with no warnings
- `cargo test --lib` → 0 failures
- Run `~/.local/bin/f install` (the freshly-installed binary) → grep stdout for the string `source ~/.local/bin/fab-shell.zsh` and the phrase "current shell" or equivalent → both present
- Re-run `~/.local/bin/f install` a second time → same hint still appears (this is the regression test for the original bug)
- Functional: in a fresh `zsh -i`, run `cd /tmp && source ~/.local/bin/fab-shell.zsh && f 1 && pwd` → pwd output is the path of item 1 in /tmp
- `git log` shows the fix commit, `git status` clean, branch `up to date with 'origin/main'`
